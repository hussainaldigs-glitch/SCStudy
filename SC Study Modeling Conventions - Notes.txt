SC Study Modeling Conventions - Notes
======================================
Standing conventions to apply on future short circuit studies, confirmed by
Hussain during the AF2-424 (Shamrock Solar) study. Check here before treating
similar situations as open assumptions.

1. Winding grounding when QP just says "Wye"
   If a QP data field for a transformer winding connection just says "Wye"
   with no grounding qualifier, treat it as Ungrounded Wye. Only use
   Grounded Wye when the QP data (or another source) says so explicitly.

2. QP table value vs. a deficiency-comment-referenced report
   If a QP field has a numeric value in the data table, but a PJM
   deficiency-review comment on that same QP says a different value from
   an external report (e.g. a FAT report) should be used, and that report
   was NOT actually provided with the study package: use the QP table
   value for the study. Do not substitute the report's value unless the
   report itself is supplied and reviewed. Note the discrepancy in the
   assumptions doc either way.

3. Joint / shared-POI projects (e.g. AF2-424 & AF2-425, or AF1-285 & AE2-306)
   Some projects share one physical facility and POI across two PJM queue
   numbers. In that case:
   - Only one QP package is needed/provided (for whichever queue is the
     data source); the QP data already describes the combined facility.
   - The POI and the facility can sit under DIFFERENT queue numbers, and
     which queue gets which is not fixed. Match how PJM's base case (and
     the stability model) already names them, and confirm with Anteneh:
       AF1-285 & AE2-306: facility under AF1-285 (the QP queue), POI is
                          'AE2-306_POI'.
       AF2-424 & AF2-425: POI is 'AF2-424_POI' (the QP queue), facility
                          under AF2-425 (Anteneh's call).
     In the calc sheet, type the facility queue into Project Name (B2) and
     the POI name into POI Bus Name (D2) instead of using their formulas.
   - If the QP / stability model doesn't say how the inverters split
     between the two queues, model the plant as one aggregated unit
     (Anteneh's call on AF2-424/AF2-425).
   - If the base case already has an older model of the facility (e.g.
     PJM's old AF2-425 plant in the AF2-424 case), delete it from the
     Without case before applying the change file. Otherwise its buses
     collide with the new ones ("Cannot make this change") and it skews
     the Without results. Check what the old POI bus connects to first.
     If it's a tap on an existing line, keep that bus and delete only from
     the lead line back, because deleting the bus deletes the line
     segments on both sides of it. (AF2-425_POI sat on the FAIR TP2 -
     REED TP2 ckt 2 line, next to AF2-444_POI.)
   - No separate short circuit study package is needed for the sibling
     queue number.

4. Check the POI tap location against the QP
   If the QP says the POI taps a line at given distances, check that the
   base case really has the POI on that line at those distances. In
   AF2-424, PJM's case had the POI connected straight to REED TP1 instead
   of 7.01 mi / 0.85 mi along the line. Anteneh said to keep the
   stability/PSSE model as is but fix it for short circuit: split the line
   at the POI and scale each segment's R, X, R0, X0 and G/B by its length
   (see AF2-424_Necessary_POI-Update.chf for an example).
